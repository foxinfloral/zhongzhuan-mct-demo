Disclaimer

  • This is a decision-support demo, non-production and not connected to production systems.
  • All results are uncalibrated. The success chance is an uncalibrated proxy, not a guarantee of making the connection.
  • A recommendation is only a recommendation, not a dispatch order; nothing is dispatched and nothing is rebooked automatically.
  • S1 = 20 min is an unconfirmed config; timeout / auto-escalation strategies are not yet human-confirmed.
  • First load may take about 15–30 seconds, occasionally longer (free-tier host cold start).

1. What is MCT?

MCT = Minimum Connecting Time, estimated per passenger, instead of fixed 60/90/120/160 min. The demo adds up the steps of a transfer (taxi-in, deplaning, bus, immigration, customs, baggage, transfer formalities, walking, APM, security) and compares the result with the available connection window.

2. Who is it for?

Hub transfer operations / OCC (Operations Control Center) and front-line staff, who see the risk tier and a recommended action; plus a plain-language passenger message view.

3. How to use the min-loop page

  1. Open min-loop.html. Nothing is estimated on page load; all fields start empty.
  2. Click 「填入演示默认场景」 (fill demo default scenario). It only fills the form: E-D / through 否 / carry-on 否 / 远机位 / 窄体 / 后舱 / 中 / 外籍 / window 55 / hybrid_t3.
  3. Click 「测算 + 决策层」 (estimate + decision layer) to run.
  4. Use the audience switch (OCC / 一线 front line / 旅客 passenger) to see each view.

The estimator page index.html works the same way (fill default, then run) and shows the Excel vs Hybrid comparison and per-node table.
